### 1. Is `src/shared/utils/period.js` server-safe?

- No `"use client"` directive (`src/shared/utils/period.js:1-7` header: "Pure ESM — no React, no DOM at import time"). Only DOM touch is `defaultStorage()` guarded by `typeof window !== "undefined"` + try/catch (`period.js:~165-171`), called only from `loadStoredPeriod`/`saveStoredPeriod` default params.
- Already imported server-side: `src/app/api/usage/stats/route.js:3` — `import { PERIOD_VALUES, periodStart, previousPeriodRange } from "@/shared/utils/period";`. Also tests import it under node (`tests/unit/period.test.js:16`, `tests/unit/usage-trends.test.js:7`).

GAP: unverified whether `@/` alias resolves for `src/lib/db` when loaded outside Next (e.g. `src/lib/home/summary.js:2` already uses `@/shared/utils/commandCenter.js`, and vitest config resolves it).
- ASSUMPTION — needs validation: `periodStart` uses `setHours(0,0,0,0)` = process-local TZ; on server that is server TZ, not browser TZ. Same semantics already apply to `/api/usage/stats` (route) and `loadDaysInRange`/`getLocalDateKey` in usageRepo.

## Traces

**Entry Points**

- `GET /api/usage/stats` `src/app/api/usage/stats/route.js:9` — accepts PERIOD_VALUES + `all`; optional `compare=previous`; `getUsageStats(period)` + `getUsageTotals` over `periodStart`/`previousPeriodRange` (calendar).
- `GET /api/usage/chart` `src/app/api/usage/chart/route.js:6` — 5 periods; `getChartData(period)` (calendar day buckets / hourly for today,24h).
- `GET /api/usage/savings` `src/app/api/usage/savings/route.js:8` — today/7d/30d; `getUsageSavings` (rolling).
- `GET /api/home/summary` `src/app/api/home/summary/route.js:8` — today/7d/30d; `getHomeSummary` (rolling).
- Client callers:
  - Home: `HomePageClient.js:37` `usePeriod(SUMMARY_PERIODS)`; `:55-62` → `useHomeUsage` (`/api/usage/stats?period=`, no `compare`), `useHomeChart` (`/api/usage/chart`), `useHomeSavings` (`/api/usage/savings`), `useHomeSummary` (`/api/home/summary`) — `useHomeData.js:17-77`. Home page thus mixes calendar (stats/chart) and rolling (savings/summary) windows for one selected period.
  - Token saver: `TokenSaverPageClient.js:45` `usePeriod(SUMMARY_PERIODS)`; `:55` `useSavingsWithFallback` → `/api/usage/savings?period=` for period + larger SUMMARY_PERIODS (`useSavingsWithFallback.js:37,54`). Toolbar options `SavingsHero.js:15` `periodOptions(SUMMARY_PERIODS)`.
  - Usage page: `usage/lib/useUsageStats.js:32` (5 periods), tile trends `usage/lib/tileTrends.js`.
  - Coercion: `usePeriod.js:34-49` `coercePeriod(urlValue, allowed)`; rewrites URL when non-canonical (`:43` comment "60d coerced to 30d").

**Contracts**

- `/api/home/summary` → `{ period, requests, previousRequests, topCombos: [{name, requests}] }` (`usageRepo.js:1397-1402`). Client reads `summary.topCombos[].name/.requests` (`HomePageClient.js:82-83`), `summary.previousRequests` (`HomePageClient.js:133` → `HomeStats.js:151` `deltaLine(requests, previousRequests)` where `requests = current.totalRequests` from `/api/usage/stats`, `HomeStats.js:132`). Current count from stats (calendar) vs previous from summary (rolling) — different window definitions in one delta. `summary.requests` and `summary.period` not read by client (grep: no match).
- `/api/usage/savings` → `{ period, estimated: true, tokensSavedEst, tokensBeforeEst, percentage, requestsWithSavings, costSavedEst|null, pricedRequests, methods, byMethod }` (`usageRepo.js:1231-1243`; `period` echoed at :1232). Client validity check: `typeof data.tokensSavedEst === "number" && Array.isArray(data.methods)` (`useHomeData.js:54-55`); fallback uses `Number(data?.tokensSavedEst) > 0` (`useSavingsWithFallback.js:7`).
- `/api/usage/stats?compare=previous` → `{ ...stats, currentTotals, previous }` (`stats/route.js:34`).
- Invalid period → 400 `{ error: "Invalid period" }` in all 4 routes.

**Patterns**: thin Next route handlers → repo functions in `src/lib/db/repos/usageRepo.js` (via `@/lib/usageDb` or `@/lib/db/index.js` barrels); pure shared util module (`period.js`) used both by client hooks and one route; URL+localStorage period state hook (`usePeriod`); i18n-extractable keyed copy objects.

## Gaps

- GAP: no server-side caller of `SUMMARY_PERIODS`; no shared constant between routes and repo for allowed periods (each route hardcodes).
- GAP: no test covers `getHomeSummary` / `getUsageSavings` windows directly (tests target test-only `src/lib/home/*`).
- ASSUMPTION — needs validation: `@/` alias usable from `usageRepo.js` in all runtimes (Next server + vitest); repo currently uses only relative imports.
